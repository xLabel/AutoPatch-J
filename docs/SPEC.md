# AutoPatch-J 项目规格

本文维护产品行为、接口和失败边界。需求决定目标，代码与测试分别提供实现和验证证据，不能反向定义需求。协作与授权见 [AGENTS](../AGENTS.md)，工程判断见 [ENGINEERING](ENGINEERING.md)，操作见 [使用手册](GETTING_STARTED.md)。

本项目托管于 GitHub Public 仓库。README 是面向外部读者的项目首页；产品规格、实现边界和工程约束在对应专题维护，任务过程留在会话。项目尚未上线，不为旧入口、配置或 schema 建兼容、迁移与双读；已有用户数据不自动删除。

## 1. 产品能力与架构

AutoPatch-J 是面向企业 Java 仓库的 Python CLI 代码审阅与修复助手，结合项目规范、长期项目知识、静态分析和 AI 判断，交付可审核、可验证的补丁。当前以员工本地交互使用为主，未来支持流水线接入；保留项目问答，不定位为通用聊天工具。

主流程：明确目标 → 收集证据并判断是否应该修改 → 起草一项完整修复 → 人工审核与修订 → 应用 → 验证并反馈下一步。扫描 finding 是候选，零 finding 不能否定用户指出的缺陷；不修改、证据不足和执行失败分别表达。

| 位置 | 职责 |
|---|---|
| `cli/` | 输入、命令、完整预览和人工决定，不编排 finding 批次或重试 |
| `application/` | 显式配置下的项目服务装配、资源所有权及初始化、重置协调，不依赖终端展示 |
| `agent/` | 一个项目 Agent、指引、SDK 适配、运行暂存与提交资格 |
| `tools/` | 受控业务函数，SDK 生成 schema、校验参数、反馈纠错 |
| `core/repair/` | 任务和提案类型、准备、审核应用、状态持久化、扫描证据和验证 |
| `core/project/` | 安全路径、源码解码与范围读取、Java 符号索引 |
| `core/conversations.py`、`core/memory/` | 官方会话与长期笔记的项目接入 |
| `llm/` | 模型装配、请求设置、结束校验和客户端生命周期 |
| `scanners/` | managed Semgrep、目标选择和扫描结果归一化 |

SDK 负责 Agent 循环、协议、参数校验、流、reasoning、历史摘要和 Memory；项目自研部分聚焦证据与可审核补丁业务。不实现 Windows Workspace、通用 shell、创建/删除/重命名源码工具、通用构建执行平台或规则治理系统。

## 2. 项目边界、命令与交互

CLI 启动目录就是目标项目根，不向上猜 Git 根。项目状态在 `.autopatch-j/`：`repair.json` 为任务与完整提案，`repair.lock` 为进程间互斥，`findings/` 保存扫描证据，`index.db` 为可重建索引，`conversations.sqlite3` 与 `memory.sqlite3` 分别保存原生消息和长期笔记，`history.txt` 保存终端输入历史。

| 输入 | 行为 |
|---|---|
| 自然语言、`@路径` | 同一 Agent 理解目标和上下文；引用路径不清空任务，也不扩大写权限 |
| `allow` | 批准界面已展示的确切写文件申请，并继续准备当前提案；不修改源码 |
| `apply` | 批准并应用已展示版本的完整提案 |
| `discard` | 结束当前待审任务，丢弃提案；不撤销已写入源码 |
| `abort` | 明确结束当前任务；中断状态先核对界面中的写入证据 |
| `/init` | 首次准备扫描器和索引，后续检查扫描器并刷新索引；保留当前任务与提案 |
| `/status`、`/scanner` | 状态诊断、扫描器状态 |
| `/new` | 结束当前任务，归档项目会话并开启空会话；保留长期笔记 |
| `/reset` | 结束当前任务、删除可重建索引并关闭运行时；保留锁文件、会话、笔记、扫描证据、导出和其他用户文件 |
| `/memory ...`、`/help`、`/quit` | 笔记管理、帮助、资源关闭与退出 |

不再使用五类 intent、审核路由分类器、批次草案队列或重定位。默认问答与讲解不改变源码、修复任务或提案，项目知识可按 Memory 约定记录。模型的语义判断由指引约束；源码修改仍由确定性的人工 `apply` 入口控制，不能宣称模型自动证明了用户意图。初始化先准备扫描器再重建索引，任一运行故障立即停止。

一次至多一项待审修复，可以包含同一问题必需的多文件改动。任务 A 待审时允许只读调查 B，但 B 不能借 A 的身份、提案或权限起草；即使同文件也须先完成 A 或由用户明确 discard/abort/new。失败或部分应用不等于结束任务，须核查并明确结束。新任务不继承旧写权限或临时要求。

## 3. 源码、工具与任务权限

### 3.1 路径与读取

路径只接受仓库相对路径，解析真实目标后须位于仓库内，且不属于 `.autopatch-j/**`，包括指向状态目录或仓库外的软链接。安全的内部源码链接可用。缺失路径直接报告，不从同名索引候选中猜目标；符号索引只用于定位，需读取当前源码。

读取可按需要扩展到仓库内关联代码；写权限单独绑定经用户 `allow` 批准的确切已有文件。目录不能直接作为写权限；扫描可展开明确目录。`@` 只提供上下文线索，不切换任务或授权写入。

写范围申请只登记新增未授权文件，保留已有待批申请；重复申请已授权文件不重开审批，工具明确提示继续准备提案。空文件申请拒绝。

源码只返回 UTF-8/GBK 无损解码文本，保留 BOM；无法无损解码即报错。返回实际行范围、总行数、截断和编码；语法块另含 `source_has_errors` 及原生 ERROR/missing 位置。行窗口前 20 后 80 行；全文和块读取按最多 300 行、约 30000 字符预算逐步展示，单个物理行保持完整。截断后可按行号继续读取。失败抛出明确错误，不把错误提示拼入源码；没有跨请求共享的 last_* 读取状态或源码缓存。

### 3.2 业务工具

| 工具 | 输入和职责 |
|---|---|
| `start_repair` | `goal, write_paths`；用户明确要求修复时准备新任务与写范围申请 |
| `request_write_scope` | `paths`；申请增加确切文件，等待用户 `allow` |
| `update_task_requirements` | `additions, removals`；新增或撤回当前任务的有效要求 |
| `scan_java` | `paths`；显式扫描 Java 文件或目录，返回候选与总数，每页 20 项 |
| `get_scan_findings` | `scan_id, offset=0`；继续读取已有扫描候选 |
| `get_finding_detail` | `finding_handle`；原始扫描身份、当前源码、适用规范及证据是否仍对应当前 bytes |
| `search_symbols` | `query, offset=0, kinds=None`；每页 20 项，返回 entries、total、next_offset 和索引过期提示；Unicode 忽略大小写的字面子串定位 |
| `search_java_references` | `name, paths, offset=0`；从当前 Java 源码获取语法引用候选及指纹、出处、分页和不完整提示，不求解接收者类型 |
| `read_source_context` | `path, line=1`；行窗口与适用祖先规范 |
| `read_source_block` | `path, line`；Java 方法、构造器或类型；未命中明确报错，不自动切换行读取 |
| `read_source_file` | `path`；有界全文，截断后继续按行读取 |
| `get_proposal` | 当前完整 diff、理由及语法结果，供解释和修订取证 |
| `get_repair_status` | 本轮任务事实、持久基线、待提交标识、写入进度、应用后验证及源码新鲜度；不复扫或写入 |
| `propose_patch` | `edits, rationale, finding_handle?`；新建或修订同一问题的完整提案 |
| `assess_issue` | `outcome, reason, finding_handle?`；明确登记不修改、证据不足或执行失败 |
| 官方 Memory 四工具 | SDK 原生 notebook 参数，见第 7 节 |

`FunctionToolName` 定义对外名称；schema 来自注解、字段描述和 docstring，不维护另一份手工 schema。参数说明包含仓库相对路径（不带交互输入的 `@`）、行号、分页、筛选、扫描句柄及有序精确替换；默认值与可空性沿用实际签名。行号拒绝 bool、字符串及小数，未知参数拒绝。工具串行执行，模型没有源码写入、批准范围、apply、discard 或任务清空工具。业务输入可纠正错误经 SDK `ModelRetry` 同轮反馈，不由 CLI 重跑整个 Agent；纠错及请求额度统一见[第 6.2 节](#62-请求额度上下文与正常结束)。

声明索引保存精确位置、源码中的签名、词法所属类型及原文件指纹，不进行 Java 类型求解。Tree-sitter 保留原生容错解析，不要求 Java 编译通过；源码有语法错误时仍返回原生识别的声明和引用，附 `source_has_errors` 与必要语法位置诊断，不宣称结构或语义完备。索引把该标记保存到 Java 文件记录及各声明，即使没有声明也保留，重启不丢失。行/全文和 AST 块读取供 Agent 独立选择，互不自动替代。相同行的重载和嵌套同名声明分别定位；返回行列从 1 开始，列按 Unicode 字符计数，不将解析用的 UTF-8 偏移当作原文件 byte offset。尚未构建索引时不创建或发布空表，搜索和统计明确提示 `/init`；成功构建后真正为空的索引可以正常返回零结果。缓存表结构不适用时提示 `/init` 显式重建自身缓存表，不迁移会话、Memory 或修复状态。完整遍历和提取后才事务替换缓存；解析器、读取或数据库故障立即报错并停止当前操作及依赖流程，不跳过文件、发布部分索引或在本次运行中回退旧快照；旧数据库保留仅为数据保护，不是故障后的替代证据。索引查询每页在调用内按真实文件复用指纹核对，不跨页缓存。CLI 补全先限定 file/dir，再取有限候选；阻塞查询交工作线程，SQLite 连接在该线程创建和关闭，输入解析、渲染、标记与报错留在活动输入事件循环。输入变化、取消或离开 prompt 后不发布过期结果或错误；已经开始的只读线程调用完成后按原生事件循环机制收尾，不强制中止线程。补全后台任务遇到真实故障时安全报告、保留当前输入及游标，暂停自动路径补全；Tab 明确重试，成功或 `/init` 成功后恢复，命令补全仍可用。不退出 CLI，不刷屏、不显示交互库默认的“按回车继续”。输入历史读写故障同样停止对应历史操作并报告，独立输入仍可使用。

Java 引用查询复用官方 Java tags 和必要补充查询，覆盖方法调用、方法/构造器引用、实例化及显式继承/实现。名称为区分大小写的完整简单名，不作子串、限定名、通配或正则展开；例如 `Disk` 匹配 `new Disk()`、`Disk::new`，限定或泛型类型取末级简单名。每页最多 20 项，整页源码片段合计不超过项目已有的 30000 字符预算；`excerpt_truncated` 不表示缺少参数或接收者，应按来源读取完整上下文。`complete` 仅表示本次合格文件范围已完整查询且没有语法诊断；有续页或语法错误时不宣称不存在引用。不可读文件或解析器故障使整次查询失败，不返回跳过故障文件的部分证据。注释、字符串中的伪调用不算调用。跨页实时解析，不冻结快照或维护长期引用缓存，不承诺完整调用图。

扫描和引用查询共用 Java 路径展开：目录遍历过滤配置忽略目录，显式文件仍按源码读取边界准入；逐项复核真实仓库路径并排除项目状态目录。读取、定位或返回引用均不扩大写权限。

### 3.3 项目规范与长期知识

系统指引仍为单个字符串，按职责与工作方式、证据与判断、任务和人工审核、规范与当前要求、长期记忆、执行事实与结果报告六组组织。具体参数格式由实际工具说明提供；原生 Memory 和摘要指引保持 SDK 默认，逐请求注入当前用户和业务绑定。

根目录 AGENTS 作为正式规范来源注入，读取源码时带回目标祖先 AGENTS；长文截断必须继续读取。用户明确提供或规范明确引用的其他规则文件按需读取，不扫描所有 Markdown。

当前要求、正式规范、长期笔记、源码和扫描证据分别标识。影响当前修复的未决实质冲突应说明并澄清，不自动创建冲突优先级引擎；用户已明确撤回或替换的要求不再重复澄清。可独立检查的要求用现有适合的语法或扫描验证，不为每条规则编写新检查器。

临时要求由修复业务入口原子更新，仅 investigating/pending 可修订。新增项逐字摘取绑定 user_request 的连续片段，不改写；正式规范和长期笔记直接作为依据，不在此重复登记。撤回项须来自当前有效列表，拒绝增删交集及空要求，去重后保留顺序；失败保留原状态，无变化不产生新候选。提示词和待审界面展示有效要求，历史对话仍可保留旧要求及撤回过程。要求随任务完成、丢弃、中止或 new 清理，不自动升级为长期笔记。

## 4. 扫描与问题判断

managed Semgrep 使用内置 Java 规则，运行版本和超时见 `AppConfig`。状态查询和扫描共用受管程序 `--version` 探测，10 秒超时；区分 missing、broken、version_mismatch 和 ready，分别展示要求版本与实际版本，不缓存历史就绪结论。缺失、探测失败或版本不符时拒绝扫描，不静默改用系统程序。

只有显式 `/init` 才准备受管运行时：安装用 filelock 互斥，在锁内复查，必要时安装或修复固定版本，完成后再次探测。锁文件保留，进程退出释放占用；不以文件存在推断程序就绪或锁仍占用。安装失败保留具体原因并终止，不继续索引；初始化成功但没有识别到 Java 类型可正常提示。

成功 payload 必须包含 list 类型 `results`、`errors`，且 errors 为空；进程、JSON、结构或任一 finding 证据出错则整次失败，不登记部分成功或冒充零 finding。证据登记还比较扫描前后文件指纹，变化则拒绝。无 Java 文件表示未扫描。

finding 包含规则、repo-relative path、fingerprint 及精确半开区域：行列从 1 开始、byte offset 从 0 开始。对外句柄为 `<scan_id>:F<n>`，不依赖隐式“当前扫描”，新扫描不重绑旧句柄。扫描快照与每文件原始指纹一起保存，起草关联补丁前再核对当前源码。

证据类型共用 Pydantic 字段校验，构造、扫描 JSON 恢复和修复状态嵌套恢复均拒绝非法整数、字符串、容器及未知字段；合法的嵌套字典恢复保持可用。成功快照要求 `ok`、合法扫描 ID 和 SHA-256、每个 finding 对应的源码指纹；读取时核对请求 ID，损坏文件保留并报错。结果归一化在单次调用内按真实文件复用原始 bytes、无损文本和行信息，区域、指纹与片段取自同份内容；扫描前后的独立读取仍保留，不跨操作缓存源码。

Optional 规则约束 `java.util.Optional` 接收者；空值调用 get 抛出的是 `NoSuchElementException`，仍须判断其他前置条件和保护。Random 只在安全敏感用途下考虑 SecureRandom；可复现模拟不据此直接判错。构造参数是否拒绝 null 依业务契约判断。静态候选不等于必须修改。

默认规则随 wheel 本地打包，共九条；扫描不下载远程规则。新增三个 WARNING 候选覆盖 String 引用相等/不等比较、BigDecimal 单参数浮点构造和直接调用 Thread.run，分别排除 null/数值比较、整数/String 构造和普通 Runnable.run。它们提示核对值比较、十进制精度及同步/异步意图，不自动判定必改。三个模式依据 Java 官方语义独立编写，来源链接保存在[规则 metadata](../src/autopatch_j/scanners/resources/semgrep/rules/java.yml)，没有复制外部 Semgrep 规则；第三方原有声明保持不变。这些模式不提供完整 Java 类型或业务分析。

Agent 逐项判断而非预生成批次补丁。`no_change` 是有效完成结论并记录理由；`insufficient_evidence` 保留待澄清任务，`execution_failure` 表示执行未完成。已有调查任务形成这些结论时，通过 `assess_issue` 登记，不只在回答中宣告。没有补丁本身不表示失败或整个仓库无问题。

## 5. 补丁安全与人工审核

### 5.1 完整提案与绑定

`edits` 为文件列表，每文件只出现一次，包含有序 `replacements`：`old_text` 非空，在前项替换结果中必须恰好匹配一次；`new_text` 可为空表示删除该片段。重复真实文件、未授权路径、空修改、匹配失效或不唯一，整项准备失败。只操作已有文本文件，不提供文件创建、删除或重命名；无法完成完整修复须说明能力限制。

所有文件先在内存准备，全部成功才生成完整提案。提案包含任务 ID、问题 ID、独立版本 ID、理由、原始与候选 bytes、两者指纹、真实目标、完整 diff、原编码与权限、编辑足迹及校验结果；内存与持久化使用同一模型，不重建另一份状态。完整 bytes 只作本地审核与应用证据，不全量注入提示词。

新建与修订使用同一个工具；修订继承原问题和 finding，不能切换绑定。导入、辅助方法、调用方可属于同一修复，不要求每次编辑与警告区域相交。Java 候选已确认语法错误时反馈纠错，不产生可应用提案；分析器不可用或运行失败则终止，不能生成可应用的 `unverified` 候选。

准备或运行失败不替换已有提案。正常或受限结束的有效候选经业务入口提交；失败、异常结束和取消不提交本轮暂存结果。受限运行仍提示“未完整完成”。每次有效修订均重新预览并等待人工 apply。

### 5.2 审核、写入与中断

所有业务状态写入共用进程间锁：提交新任务、范围、临时要求、提案、人工动作、new/reset 均在锁内重读并比较预期任务、状态、版本及提案。LLM 与人工等待在锁外，过期运行拒绝覆盖新版本；完整源码应用和写入进度保存期间持锁；复扫在锁外执行，保存验证结果时再核对版本，不覆盖后续任务。纯版本冲突作为业务拒绝反馈，仍可继续输入；明确报告源码已应用、旧验证结果未保存等事实。锁文件显式保留，不随 reset 删除。

apply 绑定界面展示的版本；先重读所有目标，比较完整原始 bytes、真实路径及提案指纹，扫描目标也核对原指纹。任一预检失败则零写入，不重定位旧提案。预检拒绝及写入中断的主因保存在当前提案的 `last_apply_error`，拒绝保存也持锁递增版本；修订提案、新任务或新一次应用清除旧原因。原因无法保存时明确提示，不伪造持久事实。

完整预检通过后先持久化 `applying` 与预期结果，再逐文件写入、保存真实进度。每文件在同目录临时文件完成编码、flush、fsync，保留 permission mode，最后再次比较原 bytes 并 `os.replace`。匹配时规范化换行，写入只替换对应 bytes，其他 bytes 不重编码；保留 UTF-8/GBK、BOM、换行与无尾换行。

多文件不承诺全部成功或自动撤销。第一个 IO、路径或持久化故障后停止本次应用并保留 CLI 输入，报告已写入、未写入和不确定项，不自动回滚或重新 apply。写后保存失败明确保留写入事实；磁盘 applying 状态阻止重放。重启只展示持久进度与当前 bytes 对照，文件等于候选不能单独证明执行历史，须人工核查再 abort/new。最终比较之后的非协作竞争写入仍可能存在，不宣称消除所有外部竞争。

损坏或不合法的修复状态明确拒绝，不当作 idle，不自动重建或迁移。交互输入前读取或展示状态失败时，报告一次并保留输入及磁盘数据，旧审核快照立即失效。独立命令不反复读取故障组件；恢复完整展示后，用户须重新决定人工操作，不自动执行故障前的输入。discard、abort、new 和 reset 不撤销已经应用的源码。

reset 由应用层在同一修复锁内协调任务结束和索引组件清理，仍绑定已展示版本。过期决定不清索引；任务已结束而索引清理失败时报告部分完成并关闭运行资源，不回滚已保存的结束事实，不清除其他用户数据。

### 5.3 应用后验证

成功写入、语法通过、目标规则未再触发、编译及业务验收是不同事实。所有文件成功写入且 applied 状态保存后才验证，失败或中断不继续复扫。记录语法结果、目标复扫及未执行的编译/测试。

有可靠扫描绑定时，将原目标半开区间依次映射经过每次真实替换；辅助文件修改不强制覆盖目标区域。验证前后确认预期 bytes 未变，复扫同路径同规则的映射足迹。足迹内仍命中为 `failed`，未命中为 `passed`；其他位置同规则不混作原目标。主动没有绑定扫描目标时为 `unverified`；缺扫描器、源码无法读取或复扫故障则报错并停止当前验证，不把故障包装为未验证后继续。已持久化 `applied` 的应用事实保留，不能改称写入中断或重复 apply。已写入状态与验证故障原因保留；保存原因也失败时明确说明。

上述 passed 仅证明目标足迹没有再触发同规则，不证明业务语义正确。没有扫描绑定的用户缺陷不能伪造目标复扫通过。编译、测试、业务验收当前未自动执行，明确 `unverified`；验证失败不回滚已批准写入，applied 事实仍保留。

`get_repair_status` 和每次主模型请求共用业务投影：提供写入进度、候选语法、应用后 checks 和失败原因，不返回完整 bytes；空 checks 明确表示尚无已保存结果。自动指令保留来源路径与一致性结论，不重复完整哈希；详细哈希可由只读状态工具获取。对照提案及扫描目标指纹核对当前源码，变化时标记旧验证不再能作为当前通过；无法读取则报错并停止依赖操作，说明持久执行事实，不能依赖旧快照继续模型请求。保留曾经写入和检查的事实，不自动复扫。apply 本身不触发 LLM；当前任务结束后清理状态，会话只保留实际收到或生成的内容，不提供完整跨任务执行历史。

## 6. LLM、上下文与诊断

### 6.1 配置与协议

Python 3.14+；固定 `pydantic-ai-slim[openai]==2.63.0`、`pydantic-ai-harness==0.63.0`、`openai==3.40.0`、`filelock==4.2.4`。`pyproject.toml` 声明直接依赖，`uv.lock` 锁定完整解析结果；开发环境使用 `uv sync --locked`，包含测试与检查工具的 `dev` 依赖组。示例启动脚本通过 uv 使用项目环境，以 demo 为工作目录，不安装开发依赖，也不自动下载 uv 或 Python。固定依赖不代表固定模型服务端版本。

| 环境变量 | 默认值与用途 |
|---|---|
| `AUTOPATCH_LLM_API_KEY` | Agent 必填；缺失仍可使用帮助、诊断和退出 |
| `AUTOPATCH_LLM_BASE_URL` | `https://api.deepseek.com` |
| `AUTOPATCH_LLM_MODEL` | `deepseek-flash` |
| `AUTOPATCH_LLM_CONTEXT_WINDOW` | 未知部署必须明确的上下文容量 |
| `AUTOPATCH_LLM_MAX_OUTPUT_TOKENS` | 未知部署必须明确的输出预算 |
| `AUTOPATCH_LLM_REQUEST_LIMIT` | 未设置或空白沿用 SDK 默认 50；正整数设置单轮上限，`none`（不区分大小写）取消上限 |
| `AUTOPATCH_DEBUG` | `false`；前台展示更多推理与有界错误详情 |

启动入口显式读取一次环境并形成不可变配置，模块导入不读取或校验环境，不读 `.env`。内置 Flash 与 deepseek-v4-pro 固定容量，不接受覆盖；其他模型必须明确容量和输出预算。正常使用默认 DeepSeek 只需 API Key；有默认值的可选参数缺失直接使用默认值。缺 Key 或显式非法容量、地址等配置问题只阻止项目服务装配和依赖功能，CLI 报错后保留帮助、诊断、显式初始化与退出，不创建替代本地运行时或发起模型请求。修改环境后重启，不自动发现模型或热重载配置。无效容量不伪造为默认 profile。旧模型名不转换，不保留已删除的批次参数。

Flash 上下文为 1,048,576 tokens，服务端最大输出 393,216；应用输出上限 128,000，安全余量 32,768，输入预算 887,808，见 [模型官方数据](https://api-docs.deepseek.com/zh-cn/api/list-models/)。DeepSeek 请求开启 thinking、reasoning_effort=max，公开 profile 选择 max_tokens；其他模型沿用 SDK baseline，不宣称已验证所有部署。摘要同模型、非流式，沿用客户端原生超时；锁定 OpenAI 客户端默认连接 5 秒、读写 600 秒，这不是整轮总时限。

SDK 管理 Chat Completions、参数 schema、流、reasoning 回传；没有第二套 parser。每个应用运行时拥有单个 asyncio.Runner 和可选异步客户端，跨请求复用，退出或装配失败时关闭；无效配置不装配运行时。Agent 使用单一具名回调对象对接展示，不维护重复的回调字典契约；不启用默认外部 instrumentation 或 SDK banner。

### 6.2 请求额度、上下文与正常结束

使用原生 [UsageLimits](https://pydantic.dev/docs/ai/api/pydantic-ai/usage/)，默认每轮 50 次逻辑模型请求，可通过 `AUTOPATCH_LLM_REQUEST_LIMIT` 调整或取消，显式零、负数及其他非法值使 Agent 不可用并报告配置错误，CLI 保留输入。摘要与工具纠错共享额度；这是一次 Agent 运行的保护，不是用户对话轮数、上下文压缩或费用上限。沿用锁定 SDK 的工具及输出各一次纠错机会、客户端最多两次网络重试，不叠加通用 retry，不重放已消费的流或业务工具流程。

只接受原始 finish_reason=stop/tool_calls，开启严格流结束标记。公开 after_model_request hook 在工具执行前拒绝截断、过滤、资源不足、aborted、缺失和未知状态；同一校验用于摘要。SDK 对缺字段的原生映射不等于证明原始字段存在。

上下文直接使用原生 [SummarizingCompaction](https://pydantic.dev/docs/ai/harness/compaction/)，能力依次装配业务绑定、压缩、Memory、循环检测和结束校验，确保 Memory 在压缩后重新核对快照。摘要没有默认触发条件；输入预算的 85% 是本项目当前保守策略，在扣除输出和安全余量后再为估算误差与额外上下文留空间，不宣称最优。保留 SDK 默认最近 20 条消息、工具依赖、模板与增量摘要。`tool_return_max_chars=None` 避免源码或规范证据在摘要格式化时被额外截为 500 字符；工具自身的有界输出不变。估算采用 SDK 的 provider usage 与原生启发式，不用 UTF-8 字节计数。当前用户原文、目标、写范围、有效临时要求和提案身份通过公开请求指令独立提供，不依赖摘要恢复。

摘要是尽力压缩：无可摘要前缀或摘要不更小时由 SDK 保留原历史，后续模型请求仍由原生策略判断是否可压缩，不设置整轮跳过标志。不裁掉必需内容，不回退清工具结果或滑动窗口。摘要失败或供应商拒绝超限即停止当前运行，保留原任务和提案，不提交本轮暂存结果；完整工具结果也可能增加摘要成本或触及容量，不声称本地估算能证明服务端一定容纳。

DetectLoops 使用 SDK 默认 nudge 行为。正常返回区分 completed、limited、cancelled，运行故障直接抛出异常交 CLI 报告并停止当前操作，保留输入。触限后不套自动续跑循环，原生消息及有效候选按第 7 节保存，用户可以继续；真实存储故障明确告知进展未确认保存并恢复输入；纯会话 CAS 冲突拒绝过期保存，保留已生成回答和实际提交事实，按业务拒绝反馈后仍可继续输入。失败或取消不替换原提案与已保存历史；此前已成功保存的长期笔记不随之后模型失败回滚。

状态投影来自本轮暂存工作副本：`base_version` 是开始运行时取得的持久基线，`pending_commit` 区分待提交变更。每次主模型请求和工具执行前短暂持锁核对基线；并发版本变化按业务冲突终止，不更换为另一任务、不提交本轮候选及会话，也不经工具纠错续跑。已经成功保存的原生 Memory 不随之回滚。

### 6.3 诊断边界

Python 报错文案集中在 [error_messages](../src/autopatch_j/error_messages.py)，只定义文字和简单模板，不依赖业务或 CLI；业务组件提供真实结果与阶段事实，现有界面边界负责报告。普通错误通常一行，部分写入或保存未确认时补必要事实，不反向依赖 CLI、不引入异常转换协议。项目服务装配失败不伪造可用运行时，终端仍提供 `/help`、`/status`、`/scanner`、`/init`、`/quit`。两个 Python 入口共用轻量启动入口，必要组件无法载入时给出明确说明；启动脚本不提前拦截缺 Key，交互启动的致命失败保留停留机会。

普通模式隐藏原始供应商错误，debug 前台展示最多 20000 字符的异常/body，按普通文字显示 Rich 标记。不主动附加请求或 headers，不保证供应商回显已脱敏。

运行故障停止当前操作及依赖流程，CLI 精简报告后保留输入；只有基本输入输出或必要运行环境不可用时才因故障退出。共享运行资源保留供独立操作使用，已关闭的实例不能继续调用。不以空数据、旧快照、替代工具或部分结果继续。普通参数错误、歧义匹配、未授权范围、过期版本、零 finding、AST 未命中保留各自业务拒绝与 SDK 原生纠错；分页、截断、主动未执行的验证及原生容错解析不是故障降级。笔记、会话或索引存储故障明确提示；contract 与编程错误继续传播。回答生成后会话保存失败保留回答，说明未保存，纯并发 CAS 拒绝不视为运行故障，不覆盖其他进程并允许继续输入。有效候选提交先于会话保存，过期业务结果不保存成有效修复回合。

## 7. 项目 Memory

### 7.1 统一会话

官方 SqliteConversationStore 保存完整 SDK 消息，包括 reasoning、工具调用、工具结果和实际摘要后的 head。每轮重新选择本项目最近未归档会话，不跨轮缓存会话 ID；问答、读取、扫描、修复及提案解释共用原生历史，不拼接另一套消息、不启用自动重放或 StepPersistence。

原生 `capture_run_messages` 在运行协程内捕获消息。完整成功及触限均可保存原生历史，触限会话 outcome 为 ready，明确任务未完成；重启后输入“继续”使用该历史和新一轮额度，不重复执行历史中已完成的工具。失败、取消不保存本轮消息。任务、提案和写权限独立持久化，模型历史不是审核状态，也不表示源码已应用。

会话读取失败不进入模型，也不以空历史继续。开始运行时，在修复业务锁内读取任务与会话快照；最终提交时同锁重读业务版本，即使只读且无业务变更也核对。有有效候选先提交，再从存储核对当前会话身份和归档状态、执行原生内容 CAS。应用层在同锁内协调 `/new` 的任务结束、归档与新建；锁定 SDK 的归档不会递增内容 revision，不能只依赖会话内容 CAS。旧运行晚到或旧 CLI 后续运行都不能复活归档会话。模型运行及人工等待在锁外，锁内仅做存储协调。

业务版本冲突不保存该轮历史；会话保存失败不撤销已提交的业务事实，明确提示进展未持久化，仍可显示已生成的回答，不覆盖其他进程。

短存储操作收到取消时，等待 SDK 后台操作结束后再释放业务锁，避免留下晚到写入。开始读取阶段取消不再进入模型；模型完成后已进入最终存储或 `/new` 切换时，先完成短存储阶段并报告实际事实，不撤销已经完成的业务提交。

### 7.2 长期笔记

官方 Memory + SqliteMemoryStore 保存 notebook，namespace=project、agent_name=main。保留默认使用指南和原生四工具 read_memory、write_memory、delete_memory、search_memory，SDK 负责注入、文件操作和版本冲突。显式 `injection_errors="raise"`（覆盖 SDK 默认 `ignore`），注入失败在模型请求前终止，Memory 工具存储故障也停止后续请求；CLI 保留输入，后续用户主动请求仍须通过相同校验；没有自研吞错包装。自动注入沿用锁定版本约 2000 tokens 的完整区块预算和主笔记 200 行预算，未注入内容可按需读取或搜索；这不限制整个会话或笔记总量。主笔记保持简短，分主题保存详细知识，新快照取代同一 Memory 的旧快照。见 [官方 Memory 文档](https://pydantic.dev/docs/ai/harness/memory/)。

可记录用户表达或确认的长期约定，以及少量已核实、后续有用的项目知识；两者分开表达。项目事实附可复核来源，使用易变信息前重新读取当前证据。优先修订已有笔记，推测不存成事实，临时进展留会话，原始源码不另存长期副本；源码事实、扫描结果或 AI 判断不自动成为项目规范。这些业务判断由指引落实，不宣称 SDK 自动理解。临时任务要求与正式规范各有来源和生命周期，未决实质冲突在当前对话澄清。

主笔记保存精简长期约定及主题入口，引用说明适用情境，较长领域知识放主题。审阅时利用已注入内容，涉及对应模块或问题再读取或搜索主题；已注入内容足够时无需重复调用。由 Agent 维护，不要求用户另建文档。原生历史保留旧快照，新运行追加更新或清空后的快照声明当前事实，不据旧历史恢复已删除笔记。

### 7.3 管理与数据边界

| 命令 | 行为 |
|---|---|
| `/memory status`、`list` | 读取实际文件列表，故障不显示成空笔记 |
| `/memory show [path]` | 显示笔记，默认 MEMORY.md |
| `/memory forget <path>` | 删除指定笔记；主 MEMORY.md 受保护，需明确修订或 clear |
| `/memory clear --confirm` | 清空笔记，保留项目会话、导出和终端历史 |
| `/memory export` | 独占创建现有笔记 JSON 导出，不覆盖旧文件 |

各项目数据库隔离，无跨项目或云端 Memory。删除笔记不擦除旧会话，指引禁止据旧会话恢复已删除笔记。旧 memory.db、memory_summary.md 和已有导出不读取、不迁移、不自动删除。损坏数据库不自动重建，也不承诺任意损坏均可导出或清空。会话和笔记可能包含用户原文、源码及 reasoning；导出只含 notebook。

## 8. 验证契约与能力限制

`uv run --locked python -m pytest -q` 是确定性完整回归，默认阻止真实 OpenAI client 和原生模型网络调用；只允许明确 FunctionModel/TestModel 或 MockTransport。扫描器与传输可以替代，补丁判断、文件 IO、状态转换、人工绑定及 SQLite 持久化保留真实组件。

真实 LLM 用例标记 live_llm，需本次明确同意并以 `--run-live-llm` 启用；先行确定性失败或首个 live 失败阻止后续请求。输出只显示模型和安全 endpoint origin。授权要求见 [AGENTS](../AGENTS.md#实现与验证)。

十一个真实 case 中，七个覆盖业务误报判断两个，以及规范冲突、要求撤回修订、源码知识重核、摘要触限重启、多文件与只读解释各一个；两个通过真实 CLI 有限终端输入驱动扫描、批准范围、预览、apply 和复扫，分别核对修复中生成笔记并在 new/重启后复用，以及按主题入口读取未注入的金额约定；两个覆盖重启后解释应用与复扫失败事实，以及分页调查普通调用、方法引用和同名干扰后保持调用方契约。检查实际模型请求、原生工具上下文、SQLite 和补丁结果，不以配置或笔记存在代替实际使用证据；不证明任意仓库均有效，也不承诺输出的每项等价性说明都自动获证实。

自动化未覆盖 Java 编译、测试、业务验收和流水线交付；静态无 finding 不证明无缺陷，摘要估算不保证服务端容量，多文件应用不具备整体回滚。平台验证以实际执行为准。
