# 独立复核操作说明

本页完整维护 AutoPatch-J 的复核流程；[AGENTS](../AGENTS.md#计划自检与独立复核)保留原则、固定配置和阅读入口。准备本阶段复核询问前必读。流程使用现有交互与子助手能力，不新增 skills、hooks、审核脚本、质量套餐、证据登记协议、永久台账或 HTML 报告。

## 1. 自检、对象与阶段选择

主助手先对照原始要求完成调查、完整对象、可自行处理的必要修正和适用验证，再展示概览。写出草案、改完文件或测试通过不单独等于完成自检，不能把第一次检查或已知必要修正交给子助手代办。

| 阶段 | 自检与概览 |
|---|---|
| 计划 | 核对原始目标、约束、相关仓库事实、用户可见变化、范围、可行性、取舍、失败边界和验收；展示主要方案、依据、实际检查及限制 |
| 产物 | 核对原始目标与获批方案、实际差异、最终行为、关联影响、测试预期和验证证据；展示产物入口、效果、结果、限制及未解决项 |

涉及代码或工程约束的计划与产物，按[工程指南](ENGINEERING.md)核对本次相关要求，并结合 SPEC 检查业务适用性；工程规则的完整条件与例外由指南维护，不在复核流程另定义一套。

涉及 Python 时，主助手自检与独立复核还须按 [Python 规范](PYTHON_STYLE.md#4-编码与审查)阅读相关 Google 原文，核对工具结果、未覆盖要求及适用例外；不能把静态检查通过或现有告警直接当作业务结论。

概览对应已准备的完整对象，不仅报标题、文件清单或“已自检”；影响判断的默认值、行为和取舍不能只藏在全文。无需披露内部推理或另写自检台账；确实无法验证时说明原因和影响，不能声称通过。

正式计划与实际产物在各自最终交付前分别取得真实选择，包括小改动。普通问答、状态更新、未定稿讨论、单纯提交推送不触发，不为触发复核强造计划或提前结束讨论。

- 计划：调查和讨论 → 完整草案 → 主助手自检、修正及适用验证 → 概览 → 选择继续讨论、复核或跳过 → 处理结果 → 最终完整计划。
- 产物：已获实施授权的实际修改 → 主助手自检、修正和验证 → 概览 → 选择复核或跳过 → 处理结果 → 最终实际交付报告。

产物复核检查实际文件、调用路径和证据，不能用交付报告代替。计划复核不授权实施或产物复核；复核、跳过也不构成提交、验收或发布授权。已有实施授权在原范围内持续有效。

对象按目标、已披露行为与授权范围判断。同目标内必要修正、澄清和排版调整，即使跨文件，也沿用本阶段已有复核或跳过选择，披露变化并补做受影响检查，必要复查交原助手。跨阶段、新增目标或实质扩大范围时另行取得决定；同文件不等于同范围。

用户可在选择前直接反馈或提问，继续讨论不等于跳过。明确跳过后正常交付，不反复劝说；最终计划或报告输出后不补发同阶段选择。后续同范围修订按已有选择处理。

## 2. 交互、等待与不可用情况

依据对象、检查结果、风险及复核价值/成本给出建议，推荐可为复核或跳过，未知成本如实说明。推荐和预选不是用户决定。每次询问说明准确对象和阶段，使用根 AGENTS 中的实际配置值，不展示参数占位符。

| 当前模式 | 允许时的询问方式 |
|---|---|
| Plan | `request_user_input` 阻塞询问，一次调用后正常等待 |
| Default | `request_user_input_async` 异步询问，受理仅表示发出 |

先核对工具可用性与允许用途。工具不可用、用途受限、调用失败或窗口消失时说明原因或已知状态，仅在环境允许时文字兜底，不伪称弹窗、不绕过工具限制。未回复、预选、超时、关闭窗口、中断或异步受理均不代表同意或跳过；没有真实选择不越过相应交付节点，不自动启动助手。

不通过循环 sleep、定时检查、重复弹窗或反复状态消息保活。异步发出后停止依赖答案的工作，保留待决定状态；恢复后先查是否已有答案。此限制不禁止正常等待子助手任务。

配置及职责以 AGENTS 为准：每阶段一名独立上下文的只读助手；不编辑、测试/构建、提交、推送、部署或再委派。需要额外验证交主助手在原授权内处理。独立上下文仍共享工作区与权限，只读任务指令不等于只读沙箱。

指定配置或子助手不可用时说明影响，由用户选择按原配置重试或明确跳过剩余复核；不自动降级、继承整段历史或换配置冒充完成。关键原始材料缺失先定向查找，仍不足时限定结论，可继续独立技术检查，不能把局部检查写成需求符合性通过。只有首步反馈时不宣称整次完成。本流程不保证完全盲审、全历史覆盖、零错误或每次必有新发现。

询问内容：计划明确“继续讨论／复核完整草案／跳过并定稿”，注明只针对计划；产物明确“复核这些实际产物／跳过”，注明包括必要修正复查。可展示概览后同轮询问，无需另增“已阅”确认。

## 3. 原始材料与两步调用

主助手先确认来源可读，提供相关消息及对象的准确定位。原始来源优先使用现有直接读取能力；否则从当前环境取得会话标识，优先在 `CODEX_HOME`，未设置时从用户目录发现 `.codex`，按该会话标识定向查找记录。不扫描无关会话、不全盘查找，不把原始聊天日志加入仓库或另造转述稿冒充原件。

按实际记录格式读取。JSONL 中用户消息可在 `response_item` 的 message/user 内容中，交互问题与答案可能分属 function call 和按 `call_id` 对应的工具结果，异步答案也可能成为后续用户消息。用 UTF-8 读取；Windows 提取时显式保持输出编码。短答“同意”须同时核对它确认的方案，受理信息不能当答案。

区分原始用户要求、已批准建议、未批准建议、自动注入约束、当前实现和待验证判断。摘要只辅助定位；只在影响判断的歧义、矛盾、证据缺口或历史引用处有限回查，依据足够或无线索即停。必要批准上下文中包含助手意见时仍保留原义，不能为隔离意见删掉用户所确认的方案。

| 材料 | 第一步 | 第二步 |
|---|---|---|
| 原始依据 | 用户消息、澄清、交互问题及实际答案、必要批准上下文 | 有新增要求时补真实来源 |
| 完整对象 | 计划全文；或获批计划、实际文件/差异、既有改动归属 | 同一对象及准确位置 |
| 项目与验证 | 适用约束、代码入口、实际命令/结果/原始证据和未执行项 | 仅补相关新证据 |
| 主助手声明 | 暂不附本轮概览、自检结论、预期复核结果或交付声明 | 用户实际看到的概览、自检说明及必要完成声明，标为待核实陈述 |

一次授权内，由同一助手分两步核查，不增加助手或重复授权：

1. 用“通用指令＋对应阶段首步正文”启动，先从原始依据和完整对象独立建立判断，返回目标、范围、初步发现和限制，允许无发现。
2. 初步反馈后向原助手补交第二步材料，沿用已有成果核对新增声明。具体矛盾或影响判断的证据缺口出现时定向补查，不默认从头全审，也不为节省调用省略必要核查。首步无发现仍完成本步，最后返回综合反馈。

首轮结束且助手空闲时用 `followup_task` 续接；`send_message` 不唤醒空闲助手。审查期间不并行修改同一待审对象，两步之间保持对象不变。用户新增要求时同步原始来源和对象变化，重新确认两步对应同一对象，不能混合旧产物和新声明。综合反馈后再由主助手修正，必要复查仍交原助手。

## 4. 可独立下发的提示词

实际调用填入真实材料和范围；没有正式计划、既有改动或验证项时注明。长期模板用相对入口和占位符，运行时可提供本机真实路径，不固化个人盘符。以下内容复述所属约束供独立执行，不另定义政策。

### 通用审核指令

```text
docs/ENGINEERING.md 相关章节，按其中条件与例外核查。
涉及 Python 时再按 docs/PYTHON_STYLE.md 的相关导航阅读 Google 原文，
检查工具覆盖边界、适用条件和例外，不以工具结果替代工程判断。
只读核查与反馈，不编辑、测试/构建、提交、推送、部署或再委派；
额外验证交主助手在原授权内处理。

直接核对给定原始用户消息、澄清和批准上下文。交互选择同时核对问题
和实际答案；短答同时读被确认内容。区分明确要求、已批准建议、
未批准建议、当前实现与推测，保留准确名称、字段、边界和后续澄清。
摘要仅辅助定位，原始依据不足时限定结论，不以主助手转述补成事实。
只围绕本次具体歧义、矛盾、证据缺口或历史引用有限补查，依据足够
或无有效线索即停止，不扫描无关会话、不扩为全仓改造。

先独立检查完整计划或实际产物、必要调用链和验证证据；不从现有
代码或测试倒推业务需求，不把测试通过或文档一致直接当作符合
用户目标的证明；测试依据的判断遵循工程指南。
首次返回初步反馈，等待第二步主助手概览、自检和必要完成声明。

空列表不能抹去旧问题，没有新证据不重开已关闭项。

返回中文简报：实际来源与对象范围、确认目标及边界、发现和限制。
首步不称整次完成；第二步返回两步综合反馈。不要大量复制原文、
敏感值或内部往返，不承诺全历史覆盖、完全盲审或零遗漏。
```

## 5. 发现处理与结束

主助手逐项核实综合反馈，在原授权内修正确认问题并完成自检和受影响验证；不采纳时说明依据，技术疑点定向验证，真正改变行为或范围的取舍另行对齐。复查提供修正位置、差异、证据及新增原始来源，仍交原助手检查受影响部分和关联边界。

确认问题在现有会话保留稳定编号及处理/关闭依据，不另建永久台账。后轮无新发现不能抹掉未关闭问题；已闭环问题没有新证据不重开。不以多轮意见替代证据，也不循环争论。

处理完成或用户明确跳过后，计划交付完整详细方案及相较概览的实质变化；产物交付实际结果、入口、验证、限制与未解决项。说明实际复核范围及状态：用户未启动而跳过、完成且无确认问题、有未解决问题、复核未完成。已启动后中断或不再继续不能写成通过；不把未来验证写为已执行。

## 6. 流程维护与核对

修改本专题时核对四段模板、UTF-8、链接/锚点、代码块及占位符；检查授权、等待、固定配置引用、两步顺序、只读职责、原始来源和失败边界未丢失，执行 `git diff --check`。不因纯流程文档变更机械运行业务或真实 LLM 测试，任务另有已批准检查时按其范围执行。

情景核对覆盖：自检未完成、概览与对象不符、未答或异步仅受理、首步无发现、原始材料缺失、配置不可用、同范围修订/跨阶段、两步对象变化、旧问题关闭及交付超出证据。未实际发生的情景只报告为情景核对，不为测试流程额外启动助手，也不据此声称已证明降低漏检率或客户端交互永久可靠。
